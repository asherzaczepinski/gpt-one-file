Training · how the numbers get nudged

Adam, Simply

Backprop tells every number which way is downhill. Adam decides how far each number should actually step. It's the reason your model got to 3.48 instead of 3.61.

The plain way, and its two problems

Plain nudging is one line: number -= learning_rate * gradient. It has two problems.

Problem 1: gradients come in wildly different sizes. In your model, some numbers always get gradients around 50, others around 0.0001. One learning rate can't be right for both.

moves 0.15

plain nudging, learning rate 0.003. way too far, it overshoots

gradient always 0.0001
moves 0.0000003

same learning rate. basically never moves

Problem 2: gradients are noisy. Each step only looks at 16 windows out of the whole text, so the gradient points a slightly different random way every step and the nudges zigzag.

Adam's fix: every number keeps two memories

For each of the 2.4 million numbers, Adam keeps two running averages and updates them every step:

average_gradient = 0.9  * average_gradient + 0.1  * gradient       # which way it's been pointing
average_squared  = 0.95 * average_squared  + 0.05 * gradient ** 2  # how big its gradients usually are

step = learning_rate * average_gradient / sqrt(average_squared)

Memory 1 fixes the noise. It's mostly the old average plus a bit of the new gradient, so it remembers roughly the last 10 steps. If the gradient keeps pointing the same way, the average builds up. If it keeps flipping, the flips cancel out.

Memory 2 fixes the sizes. Dividing by "how big this number's gradients usually are" cancels out the size. A number with gradients around 50 and a number with gradients around 0.0001 both end up stepping about learning_rate.

The startup fix

Both memories start at 0. After step 1, average_gradient is only 0.1 * gradient, way too small. So Adam divides by (1 − 0.9step): at step 1 that's dividing by 0.1, which gives the real gradient back. A few dozen steps in, 0.9step is about 0 and it's dividing by about 1, so it stops mattering. The table above includes this fix.

Why it needed 16 windows in your runs

Adam takes close to a full-size step whenever the direction looks consistent. With just 1 window per step, every gradient is so noisy that Adam kept taking full-size steps in random directions, and run2 got stuck at a test loss of 4.04. Averaging 16 windows made the gradients smooth enough, and run4 reached 3.48, the best so far.

In one line: Adam = move each number by about the learning rate, in the direction its gradient has consistently been pointing, no matter how big or small its gradients are.
