NumPy vs CUDA vs CuPy, in plain words

NumPy does its math on the CPU, the main chip in your Mac. A CPU has a few very fast, very smart cores (your M4 has 10).

A GPU is a different chip with thousands of small, simple cores. Each one is slower than a CPU core, but a matrix multiply is millions of separate multiply-and-adds that don't depend on each other, so thousands of cores can each do a slice at the same time.

CUDA is NVIDIA's system for running code on their GPUs. It's low-level and normally written in C++.

CuPy is the bridge: a Python library that copies numpy's functions (same names, same arguments) but runs each one on the GPU through CUDA. That's why the change is mostly np. → xp., where xp is CuPy on the pod and plain numpy on your Mac.

NumPy (yours)CuPy (the CUDA version)
Where the arrays liveyour computer's normal memory (RAM)the GPU's own memory. a GPU array is invisible to numpy, so you can't hand one to an np. function
Who does the maththe CPUthe GPU's thousands of cores
The codenp.exp(x), a @ bxp.exp(x), a @ b (same names, same shapes, same answers)
Moving datanot neededxp.asarray(a) copies CPU → GPU. a.get() copies GPU → CPU (that's to_cpu). copying is slow, so it happens as rarely as possible
Number typefloat64 (64-bit)float32 (32-bit): most GPUs do 32-bit math many times faster. tiny rounding differences, no real effect on training
Small workfinewasteful. each operation costs a little time just to start on the GPU, so it needs big chunks of work. that's why the CUDA version batches 16 windows together
Waitingevery line finishes before the next one startsPython just queues work for the GPU and keeps going. it only waits when it needs an actual number back, like float(loss)

Why batching matters so much here. Your model's matrices are small (one window is 64 × 128). Handing a GPU one window is like giving one sheet of homework to a classroom of 5,000 kids: most of them sit there. Stacking 16 windows into one (16, 64, 128) array gives every step 16 times more work at once, for about the same startup cost. And as the checks above show, one batch of 16 gives the exact same gradient as your loop over 16 windows, because the loss is an average either way.

Running it on RunPod

Same steps as in RUNPOD.txt, just with this file. Upload main_functionized_cuda.py, stories.txt and runpod_setup.sh, then in the pod's terminal:

bash runpod_setup.sh                                          # installs cupy and checks the GPU works
nohup python main_functionized_cuda.py > cuda_run.log 2>&1 &   # trains, then saves and writes 3 stories
tail -f cuda_run.log

When it's done, download main_functionized_cuda_model.pkl. It's saved as plain numpy, so it loads on your Mac too. Stop the pod after.

The model and training are the same size as on your Mac, so this run should only take a minute or so on the GPU. The real payoff comes when you make the model or the training text bigger (level B or C on the Training Time page).
